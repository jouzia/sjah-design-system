# Accessibility & UX Rules

- All controls must be keyboard operable and show a visible focus state.
- Use semantic landmarks: header, nav, main, footer.
- Give icon-only buttons accessible names and tooltips where useful.
- Inputs require persistent labels; placeholders are examples, not labels.
- Errors should explain the problem and how to recover; associate inline errors with fields.
- Announce OTP sent, validation failures, loading states, and successful actions with accessible live regions.
- Do not communicate status through color alone.
- Meet WCAG AA contrast targets for text and meaningful UI components.
- Respect reduced-motion settings.
- Manage focus correctly when dialogs open/close; trap focus only for modal dialogs.
- Confirm destructive actions and provide undo when practical.
- Ensure the AI widget can be closed, keyboard navigated, and used without a mouse.
- Include privacy information and a way to report incorrect AI output when appropriate.
